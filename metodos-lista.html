Lista de métodos JavaScript / API.

Inventario de los métodos y endpoints de Unified Checkout Solutions (Mastercard) que se invocan en la integración de Click to Pay. Reconstruido literalmente desde la documentación oficial de los 3 casos de uso: First Time User, User Recognized through Email/Mobile Lookup y Recognized User.

Tabla general

Método / Componente / Endpoint Tipo Casos Paso del flujo Alcance · qué hace según la documentación
init() JS Library 1 · 2 · 3 · 4 Step 1 · Initialize the JS Library Inicializa la librería JS de Click to Pay. En el caso First Time User puede recibir el parámetro checkoutExperience para decidir en qué punto se inscribe al consumidor en Click to Pay.
getCards() JS Library 1 · 2 · 3 · 4 Step 1 · Check if Consumer is Recognized Verifica si el navegador / aplicación del consumidor está reconocido por alguna red Click to Pay. Devuelve lista de maskedCard (caso 3/4: reconocido), respuesta vacía (caso 1: primera vez) o mensaje "not recognized" (caso 2: no reconocido).
authenticate() JS Library 1 · 2 Step 2 · Identify and Authenticate Consumer Verifica si una identidad (correo / celular) es conocida por algún sistema Click to Pay y ejecuta el OTP cuando aplica. Recibe iFrame windowRef y accountReference. Encapsula idLookup(), initiateValidation() y validate() — Mastercard recomienda usar authenticate() en lugar de los tres métodos antiguos.
encryptCard() JS Library 1 · 4 Step 3 (caso 1) · Encrypt Card and Checkout Enmascara los datos del PAN. Devuelve un objeto encryptedCard que se usa como entrada de checkoutWithNewCard(). El PAN nunca viaja en claro hacia el comercio.
checkoutWithCard() JS Library 2 · 3 Step 3 (caso 2) / Step 2 (caso 3) · Checkout Procesa el pago con una tarjeta ya inscrita en el perfil Click to Pay. Recibe parámetros como payloadRequested = "AUTHENTICATED" bajo authenticationPreferences para autenticación de transacción con passkey. Devuelve checkoutResponse con checkoutActionCode = COMPLETE.
checkoutWithNewCard() JS Library 1 · 4 Step 3 · Encrypt Card and Checkout Procesa el pago con la encryptedCard y permite inscribir la tarjeta en el perfil Click to Pay. Acepta recognitionTokenRequested = true para el consentimiento "Remember Me" y payloadRequested = "AUTHENTICATED".
SRC Card List Componente UI 2 · 3 · 4 Mostrar lista de tarjetas Componente UI provisto por Mastercard para construir la pantalla con la lista de tarjetas (maskedCard list) que el consumidor puede seleccionar para el checkout.
setting up the JavaScript library Setup 1 · 2 · 3 · 4 Pre-requisito (antes del Step 1) Acción de onboarding del integrador para incorporar la JS Library de Click to Pay en su página. Es prerequisito explícito de los 3 casos documentados.
POST /checkout REST API 1 · 2 · 3 · 4 Step 4-5 · Fetch and Decrypt Payload Endpoint server-side. Recupera el encryptedPayload de la transacción. Usa como argumento el merchant-transaction-id devuelto en checkoutResponse. El payload viene firmado / cifrado en checkoutResponseJWS (JWE) y se descifra con la clave privada del integrador.
Payment Authorization (DSRP) Server 1 · 2 · 3 · 4 Step 6 · Payment Authorization El integrador envía el payload descifrado para la autorización de pago. Para transacciones tokenizadas se siguen las guías DSRP (Acquirer Implementation Guide + AN3363).
POST /confirmations REST API 1 · 2 · 3 · 4 Step 7 · Send Confirmation Reporta a Unified Checkout Solutions el resultado de la transacción (irrespective of the transaction status). Devuelve 204 No Content si UCS recibe la confirmación correctamente. Envía los campos checkoutEventType y checkoutEventStatus según el escenario (Authorize, Cancel, Refund…).

Método Tipo Estado Alcance

Secuencia por caso de uso (según documentación oficial)

Caso 1 · First Time User

  1. Step 1 · Initialize the JS Library and Check if Consumer is Recognized. Al cargar la página, llamar init() y getCards(). getCards() devuelve respuesta vacía → consumidor no reconocido.
  2. Step 2 · Validate Consumer Identity and Enroll a Card. El consumidor ingresa correo / celular / dirección de envío. Llamar authenticate() con el accountReference. Devuelve lista vacía. Presentar formulario de captura de tarjeta + consentimiento "Remember Me".
  3. Step 3 · Encrypt Card and Checkout. Llamar encryptCard() → encryptedCard. Llamar checkoutWithNewCard() con recognitionTokenRequested = true. Opcional: payloadRequested = "AUTHENTICATED" para passkey. Recibir checkoutResponse con checkoutActionCode = COMPLETE.
  4. Step 4 · Fetch and Decrypt Payload. Server llama POST /checkout con merchant-transaction-id → encryptedPayload. Descifrar con la clave privada.
  5. Step 5 · View the Decrypted Payload. JSON con la transacción según dynamicDataType (CARD_APPLICATION_SHORT_FORM / NONE).
  6. Step 6 · Payment Authorization. Server envía el payload descifrado para autorización DSRP.
  7. Step 7 · Send Confirmation. Server llama POST /confirmations → 204 No Content.

Caso 2 · User Recognized through Email/Mobile Lookup

  1. Step 1 · Initialize the JS Library and Check if Consumer is Recognized. Llamar init() y getCards() al cargar la página. getCards() no devuelve maskedCard → "not recognized".
  2. Step 2 · Identify and Authenticate Consumer. El consumidor ingresa datos de contacto. Llamar authenticate() pasando iFrame windowRef y accountReference (correo / celular). Mastercard muestra OTP en el iFrame con "Remember Me" si se envió requestRecognitionToken=True. authenticate() responde con lista de tarjetas y recognitionToken. Mostrar lista con SRC Card List.
  3. Step 3 · Checkout. El consumidor selecciona tarjeta. Llamar checkoutWithCard() (o checkoutWithNewCard() si ingresó tarjeta nueva). Opcional: payloadRequested = "AUTHENTICATED" bajo authenticationPreferences. checkoutResponse con checkoutActionCode = COMPLETE.
  4. Step 4-7. Igual al caso 1: POST /checkout → descifrar payload → autorización DSRP → POST /confirmations.

Caso 3 · Recognized User

  1. Step 1 · Initialize the JS Library and Fetch the Card List. Llamar init() y getCards() al cargar la página. Como el dispositivo es de confianza, getCards() devuelve la lista de maskedCard de inmediato. Si no la devolviera, fallback a authenticate() (caso 2) o flujo First Time User. Mostrar lista con SRC Card List.
  2. Step 2 · Checkout. Consumidor selecciona tarjeta. Llamar checkoutWithCard() (o checkoutWithNewCard()). Opcional: payloadRequested = "AUTHENTICATED". checkoutResponse con checkoutActionCode = COMPLETE.
  3. Step 3-6. POST /checkout → descifrar encryptedPayload → autorización DSRP → POST /confirmations.

Caso 4 · Agregar nueva tarjeta (variante)

⚠️ La documentación oficial no tiene una página dedicada para este caso. Se reconstruye combinando el Step 1 del caso 3 (usuario reconocido) y el Step 3 del caso 1 (encriptación + checkoutWithNewCard()) — ambos pasos son citas literales de la documentación.

  1. Step 1 (del caso 3). init() y getCards() → lista de maskedCard. Mostrar con SRC Card List + opción "Ingresar tarjeta manualmente".
  2. Captura de tarjeta nueva. Formulario inline para PAN, vencimiento y CVC.
  3. Step 3 (del caso 1). encryptCard() → encryptedCard. checkoutWithNewCard() con recognitionTokenRequested = true y opcional payloadRequested = "AUTHENTICATED". checkoutResponse con checkoutActionCode = COMPLETE.
  4. Server. POST /checkout → descifrar → autorización DSRP → POST /confirmations.

Lista de métodos JavaScript / API.

Inventario completo de los métodos del SDK de SRC (EMVCo) y de Unified Checkout Solutions (UCS) que se invocan en la integración de Click to Pay sobre el checkout de Éxito — con el caso de uso donde aplican, el paso del flujo y el alcance de cada uno.

Tabla general

Método / Componente Tipo Casos Paso del flujo Alcance · qué hace
Sessions API · captureContext UCS 1 · 2 · 3 · 4 Inicio del checkout Crea un contexto de sesión seguro con SRC y devuelve un JWT (captureContext) que se usa para montar Unified Checkout. Todas las llamadas posteriores se autorizan con ese token.
uc.mount() UCS 1 · 2 · 3 · 4 Inicio del checkout Monta el componente de Unified Checkout en la página del comercio con el captureContext; deja listos los web components y eventos del SDK.
src.init() SRC SDK 1 · 2 · 3 · 4 Al seleccionar "Tarjeta crédito o débito" Inicializa el SDK de SRC. Prepara la sesión para identificar al consumidor y desencadenar el resto del flujo de Click to Pay.
src.isRecognized() SRC SDK 1 · 2 · 3 · 4 Card loader Determina si el dispositivo / navegador ya está reconocido como de confianza. true → casos 3 y 4 (sin OTP); false → casos 1 y 2.
src.idLookup(identity) SRC SDK 2 Card loader Busca un perfil Click to Pay por correo o número de celular del consumidor. Devuelve si existe un perfil asociado y los canales de validación soportados.
<src-card-loader> Componente 1 · 2 · 3 · 4 Paso 04 · Card Loader Pantalla "Click to Pay is looking for your linked cards…" con escudo + spinner; cubre el tiempo de identificación del consumidor.
<src-otp-input>
+ loadSupportedValidationChannels		 Componente 2 Paso 05 · OTP Recibe el array supportedValidationChannels ({validationChannelId, identityType, maskedValidationChannel}). Muestra el identificador enmascarado, "¿No eres tú?", H1 "Click to Pay encontró tus tarjetas vinculadas", casillas de OTP y enlaces de reenvío.
src.validate(otpCode) SRC SDK 2 Paso 05 · OTP · Continuar Valida con SRC el código de un solo uso ingresado por el consumidor. Devuelve éxito o error.
src.getCards() SRC SDK 2 · 3 Selección de tarjeta Devuelve la lista de tarjetas tokenizadas del consumidor reconocido (sólo los identificadores digitales — nunca el PAN real).
<src-consent> Componente 1 Tras los 4 primeros dígitos Recoge el consentimiento de inscripción ("Guardar mi información con Click to Pay") junto con los Términos y el Aviso de Privacidad. Aparece cuando la tarjeta resulta elegible.
src.encryptCard(cardData) SRC SDK 1 · 4 Antes de pagar Cifra los datos de la tarjeta nueva en el dispositivo del consumidor. El PAN real nunca viaja en claro hacia el comercio ni hacia el backend.
src.checkoutWithCard(srcDigitalCardId,
complianceSettings)		 SRC SDK 2 · 3 Clic en Pagar Procesa el pago con una tarjeta ya vinculada al perfil Click to Pay, identificada por su srcDigitalCardId. Aplica ComplianceSettings con los términos legales del comercio.
src.checkoutWithNewCard(encryptedCard,
complianceSettings)		 SRC SDK 1 · 4 Clic en Pagar Procesa el pago con la tarjeta cifrada nueva e inscribe la tarjeta en el perfil Click to Pay (caso 1: crea el perfil; caso 4: añade a uno existente).
ComplianceSettings Configuración 1 · 2 · 3 · 4 Llamadas de checkout Objeto con las URLs de Términos y Aviso de Privacidad del comercio. Mastercard exige enviarlo en cada checkout* para asegurar el cumplimiento legal.
authorize (server-side) Server 1 · 2 · 3 · 4 Tras checkout SDK El backend del comercio toma el transient token que devuelve el SDK y envía la transacción al adquirente / red para autorización con el emisor.
3DS Server / Emisor 1 · 2 · 3 · 4 Durante la autorización Paso de verificación adicional invocado por el emisor cuando lo considera necesario (OTP bancario, biometría, app push). Reduce fraude sin bloquear compras legítimas.

Eventos del componente <src-otp-input>

Evento Tipo Casos Disparador Alcance
resendOtp Evento 2 Clic en "Reenviar Móvil" o "Reenviar Email" El componente avisa al integrador que el usuario quiere reenviar el código. El comercio puede solicitar a SRC un nuevo OTP por el canal elegido.
notYouRequested Evento 2 Clic en "¿No eres tú?" El componente notifica que el consumidor quiere identificarse con otro correo / celular. El integrador puede reiniciar el flujo con una nueva identidad.

Secuencia por caso de uso

Caso 1 · Nuevo usuario

  1. Sessions API · captureContext · uc.mount()
  2. src.init() + src.isRecognized() → false · src.idLookup() → sin perfil
  3. <src-card-loader> mientras se identifica
  4. Entrada manual de tarjeta (PAN, vencimiento, CVC)
  5. Tras los 4 primeros dígitos → <src-consent> (consentimiento de inscripción)
  6. src.encryptCard(cardData) → src.checkoutWithNewCard(encryptedCard, ComplianceSettings)
  7. Backend authorize + 3DS si el emisor lo invoca
  8. Página de pedido confirmado de Éxito

Caso 2 · Reconocido por correo / teléfono

  1. Sessions API · captureContext · uc.mount()
  2. src.init() + src.isRecognized() → false + src.idLookup(email) → perfil encontrado
  3. <src-card-loader>
  4. <src-otp-input> · loadSupportedValidationChannels(channels) · eventos resendOtp / notYouRequested
  5. src.validate(otpCode)
  6. src.getCards() → lista de tarjetas
  7. src.checkoutWithCard(srcDigitalCardId, ComplianceSettings)
  8. Backend authorize + 3DS si el emisor lo invoca
  9. Página de pedido confirmado de Éxito

Caso 3 · Usuario reconocido

  1. Sessions API · captureContext · uc.mount()
  2. src.init() + src.isRecognized() → true (sin OTP)
  3. <src-card-loader> (breve)
  4. src.getCards() → lista de tarjetas al instante
  5. src.checkoutWithCard(srcDigitalCardId, ComplianceSettings)
  6. Backend authorize + 3DS si el emisor lo invoca
  7. Página de pedido confirmado de Éxito

Caso 4 · Agregar nueva tarjeta

  1. Sessions API · captureContext · uc.mount()
  2. src.init() + src.isRecognized() → true
  3. <src-card-loader> y src.getCards()
  4. El usuario elige "Ingresar tarjeta manualmente" → captura PAN, vencimiento, CVC + consentimiento
  5. src.encryptCard(cardData) → src.checkoutWithNewCard(encryptedCard, ComplianceSettings)
  6. Backend authorize + 3DS si el emisor lo invoca
  7. Página de pedido confirmado de Éxito

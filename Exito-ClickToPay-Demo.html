Punto 1 · Ventajas

Por qué Click to Pay

Click to Pay reemplaza el formulario de tarjeta tradicional por una billetera de red (Mastercard, Visa, Amex, Discover) basada en el estándar EMVCo® SRC. Beneficia por igual al comercio y al tarjetahabiente.

🏪 Para el comercio (Éxito)

  • Más conversión: menos campos y abandono; el pago en 1 clic acorta el checkout drásticamente.
  • Mayor tasa de aprobación: datos tokenizados y enriquecidos que las redes aprueban mejor que un PAN manual.
  • Menos fraude y contracargos: tokenización de red + autenticación (OTP / 3-D Secure / passkeys).
  • Cero datos sensibles (PAN) en Éxito: alcance PCI-DSS reducido; la red guarda y cifra la tarjeta.
  • Una sola integración: Unified Checkout Solutions entrega varias redes y métodos con un solo SDK.
  • Tarjetas siempre vigentes: el Account Updater de la red actualiza tarjetas vencidas/renovadas.
  • Optimizado para móvil: coherente con el alto tráfico móvil de exito.com.

👤 Para el tarjetahabiente

  • Sin teclear la tarjeta: se reconoce y paga en 1 clic en cualquier comercio con Click to Pay.
  • Reconocimiento entre comercios: se enrola una vez y su billetera lo acompaña por la web.
  • Más seguro: el número real nunca viaja ni se almacena en la tienda; se usa un token.
  • Control y transparencia: elige qué tarjeta usar, gestiona su billetera y “No eres tú”.
  • Experiencia consistente: misma jornada conocida en todos los sitios — confianza.
  • Multidispositivo: reconocimiento por correo/teléfono o por dispositivo vinculado.
Punto 2 · Cómo funciona

Arquitectura de Unified Checkout Solutions

Éxito (sobre VTEX) integra una sola vez: el backend genera un capture context y la librería de Unified Checkout monta la interfaz. Mastercard orquesta por dentro los métodos de Click to Pay (capa SRC).

Servidor · Éxito

1. Crear la sesión

El backend llama a la Sessions API con el monto, país y orígenes. Devuelve un capture context (JWT firmado con llaves de cifrado de un solo uso).

POST /sessions → captureContext
Cliente · Navegador

2. Montar Unified Checkout

La librería JS se inicializa con el JWT y monta el botón/componente de pago en el checkout de Éxito.

new UnifiedCheckout(jwt).mount()
Cliente · Click to Pay

3. Reconocer y pagar

Click to Pay reconoce al consumidor (correo/teléfono o dispositivo), valida con OTP y muestra sus tarjetas. Devuelve un token transitorio.

idLookup · validate · getCards · checkout
Servidor · Éxito

4. Autorizar

El backend autoriza el pago con el token transitorio (más 3-D Secure si aplica). Nunca toca el PAN real.

POST /payments (transientToken)
Capa de orquestación — Unified Checkout Solutions (Sessions API + librería JS) Capa Click to Pay — métodos SRC que Mastercard ejecuta dentro de cada momento
